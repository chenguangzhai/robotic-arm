# 四轴机械臂 · 开发总结

> STM32F103C8T6 + 6 路舵机机械臂。三连杆逆运动学、笛卡尔直线插补（梯形加减速）、
> 串口文本协议、单文件网页上位机（2D/3D 姿态可视化 + 工作空间底图）、关节空间示教回放。
>
> 本文是**结论版**：只留"是什么、为什么、参数多少"。
> 公式推导、逐步验证命令、14 条踩坑的完整复现过程见 **[工程开发总结.md](工程开发总结.md)**（详细记录版）。

## 1. 项目一览

| 项 | 内容 |
|---|---|
| 主控 | STM32F103C8T6，72 MHz / 64 KB Flash / 20 KB RAM |
| 框架 | STM32 HAL（CubeMX 生成） + CMake + arm-none-eabi-gcc，无 RTOS |
| 自由度 | 底座偏航 + 肩 + 肘 + 腕 = 4 轴，另有夹爪旋转、夹爪开合 |
| 末端控制 | 笛卡尔 `(x, y, z)`，单位**米** |
| 输入通道 | 4 个按键 + 串口指令 + 网页上位机 |
| 资源占用 | Flash 49828 B（76%）、RAM 7808 B（38%），`_etext = 0x0800B0A0` |
| 示教容量 | 64 点 × 14 B，存于 Flash 最后一页 `0x0800FC00` |
| 实测指标 | IK→FK 闭环误差 **0.0000 mm**（6669 个可达点）、可达率 **66.3%**、单点精度 1~3 cm |

**版本**：`archive/1.0` 逆解+按键+OLED → `archive/2.0` 加串口/运动控制/夹爪 →
根目录（3.0/3.1）加示教回放、梯形加减速、纯偏航模式。

## 2. 系统构成

```
main.c        主循环：按键 + 串口汇成同一份目标
  ├─ protocol.c   切行 · 解析 · 分发（不驱动舵机）
  ├─ motion.c     笛卡尔沿直线按时间推进（要逆解）   ┐互斥
  ├─ play.c       关节空间示教/回放（不走逆解）      ┘
  ├─ model.c      逆运动学 + 正解（只算角度）
  ├─ Servo_motor.c 角度 → PWM 脉宽
  └─ uart_app.c   环形缓冲 + DMA（只搬字节）
```

**分层铁律：每层不知道上下层内部。** `uart_app` 不懂什么是"命令"；`protocol` 不懂 DMA、
不驱动舵机；`motion`/`play` 不关心指令从哪来；`model` 不知道舵机怎么接线。
收益是**加一条输入通道（蓝牙/4G）时执行层零改动**。

主循环里四件事的顺序不能乱：

```c
Protocol_Poll();   // 解析命令 → 改目标 / 记点 / 启停回放（非阻塞）
// 按键 → Motion_SetTarget()（回放期间只读不执行）
Motion_Tick();     // 按时间推进一次
Play_Tick();       // 回放插值；没在回放就一句判断
// OLED 刷新（运动/回放中跳过区间扫描）
```

> 构建坑：`CMakeLists.txt` **显式列源文件**，新增 `.c` 必须同时加进 `target_sources`
> 和 `target_include_directories`，否则 `undefined reference`。可执行目标名是 `OLED`。

## 3. 五个关键决策

这一节是整个工程真正花时间的地方——不是"怎么写"，而是"为什么这样写"。

### 3.1 示教记**关节角**，不记坐标

记坐标看起来更自然，但会立刻撞上三条既有约束：工作空间只有 66.3% 可达且**非凸**、
路径校验会拒掉中途穿洞的直线、单点精度只有 1~3 cm。

记角度把三条全部绕开：**回放不做逆解、不做路径校验**，直接下发 6 路 PWM。
精度要求也从"绝对精度"退化成"重复精度"——同一台机器回到同一组角度的偏差远小于标定误差。
代价：回放点只能来自示教，且关节空间插值下**末端走弧线**。

### 3.2 按**时间**推进，不按主循环圈数

旧做法"每圈走 1 mm"的根本问题：主循环周期不固定（OLED 刷新十几毫秒、区间扫描几十毫秒），
末端速度随刷新节奏抖动。改成 `dt = HAL_GetTick() - s_last_ms` 后速度才与刷新率解耦。

三个保护：`dt == 0` 直接返回；`dt > 50 ms` 截断（主循环被卡过，别一步跳几毫米）；
累加器不足 0.5 mm 先攒着（不为 0.05 mm 反复解逆解）。

### 3.3 三重校验，顺序有讲究

```
1) 数值范围  → 先挡"把毫米当米"的笔误，不必浪费逆解
2) 终点可达  → 目标本身不在工作空间，直接拒
3) 路径可达  → 起终点都行，但中间穿洞，也拒
```

第 3 步不可省：三连杆工作空间是**带洞的壳**，起终点都可达而中途不可达时，
末端会走到洞边卡住，表现为"走到一半顿一下"。校验失败时目标与运动状态**原封不动**。

> 副作用：远距离遥控变"挑"，斜穿边界容易回 `ERR:PATH`。嫌烦可关 `MOTION_PATH_CHECK`。

### 3.4 加减速用 `sqrt(2ad)` 上限，不按比例分配时间

速度被两条上限夹住：`s_vmax`（人设巡航速度）与 `sqrt(2·a·剩余距离)`（还刹得住的最大速度），
每轮变化不超过 `a·dt`。三段（加速/匀速/减速）是同一公式的自然结果，短距离自动退化成三角形。

`sqrt(2ad)` 就是匀减速的运动学解 `v² = 2as`，保证剩余距离内恰好把速度降到 0。
按比例分配只能得到"看起来像梯形"的形状——一旦巡航速度被 `V` 改掉，减速段就刹不住。

> **反直觉的一处**：`Motion_SetTarget` 不再清速度与累加器。按键遥控每轮都改目标（5 mm），
> 每次都清会导致**按住键手臂不动**（累加器永远攒不到 0.5 mm、速度永远重新起步）。

### 3.5 纯偏航独立成 `Y` 命令，不改 `M` 的 z 语义

用户反馈"改 z 时四个关节一起动"——这不是 bug。`z` 是**横向米数**不是角度，
`yaw = atan2(z,x)`、`r = hypot(x,z)`，改 z 时偏航角与半径同时变，末端沿直线横移、
到基座距离必然变长，肩肘腕必须补偿（实测 10 cm 横移只让半径长 17 mm，肘却动了 13.4°）。

把 `M` 的 z 改成角度会引入**量纲混合**：`Motion_Dist`、速度上限、路径采样全部失去物理意义。
所以拆成两条命令：`M` 管"到空间哪个点"，`Y` 管"朝哪个方向"（柱坐标，进入时锁定 r、h）。

实现上三条铁律：① 只写底座那一路 PWM，**不走 `model_now()`**（重解三关节时
`(uint16_t)` 截断在浮点尾数压线时可能翻 1 位）；② r、h 进入模式时锁定，不每步反算
（否则浮点误差累积，转十次半径就漂了）；③ `Motion_SetYaw` 不清角累加器（同 3.4 的坑）。

## 4. 逆运动学

**坐标约定（最容易混）**：`x` 正前方水平距离、`y` **离地高度**（不是纵深）、`z` 水平面内横向偏移。

俯仰平面是标准三连杆，末端只有 `(r, h)` 两个约束而关节有 3 个 → **多 1 个冗余自由度**。
处理方式是放弃对姿态角 α 的约束，用冗余度挑「|α| 最小」的解：从 α=0（夹爪水平）起
向两侧以 5° 步长放宽，第一个可行姿态即答案——能水平就水平，够不到才倾斜。
比锁死腕关节的工作空间大得多。

余弦定理只给出 `|th2|`，**肘上/肘下两种构型都试**（实物是肘下工作；早期只试肘上，
可达率只有 44.9%，两构型都试后升到 61.2%，配合其他修复最终 66.3%）。

**舵机标定**：`a = ZERO + DIR × th_deg`

| 关节 | 几何零位 | ZERO | DIR |
|---|---|---|---|
| 肩 a1 | 大臂向前水平 | 180 | −1 |
| 肘 a2 | 小臂与大臂成直线 | **178** | +1 |
| 腕 a3 | 夹爪与小臂同轴 | 90 | −1 |

> 肘的 ZERO 是 **178 而非 180**：实物所有姿态恒定比目标高约 2°，用零位减 2 做全局补偿。
> 偏高 1.5° 填 178.5，偏高 2.5° 填 177.5;补偿过头就往 180 回。同时 a2 行程上限必须保持 180
> ——放宽到 182 会让 `th2 ∈ [0,4°]` 的**肘上构型被误接受**。

**底座**：`waist = atan2(z,x)·180/π + 90`，0~180° 只覆盖 `x ≥ 0` 半平面，
`x < 0`（目标在背后）在 `solve()` 开头就判不可达（早期是静默钳位，会甩到正侧面还回 `OK`）。

**典型解**：`(0.28,0.10,0)` → B90 S120 E69 W42；`(0.36,0.08,0)` 全伸直 → S180 E178 W90。

## 5. 串口协议

115200 8N1，单行文本，参数间空格/Tab/逗号均可，大小写不敏感，`\n` 或 `\r\n` 结尾。

| 指令 | 说明 |
|---|---|
| `M x y z` | 移动到 `(x,y,z)`（**米**）。`OK`=已受理，到位推 `DONE` |
| `Y <度>` | 纯偏航，锁定当前 r、h，±88° |
| `G 0\|1` | 夹爪 0=张开(0°) / 1=收紧(60°)，只驱动 PA7 |
| `R <角度>` | 夹爪旋转 0~180°，0=平行地面，**60=垂直地面**（实测） |
| `V <mm/s>` | 末端巡航速度 20~150（`S` 为别名） |
| `T [ms]` / `A a1..a6 [ms]` | 记当前姿态为一点 / 追加指定角度的一点 |
| `L` / `D n` / `C` | 列点表 / 删第 n 点 / 清空（只清 RAM） |
| `P [遍数]` / `X` | 回放（无参=无限循环）/ 停止 |
| `W` | 点表写 Flash |
| `?` | 查询状态 |

**状态应答**（固定 11 字段）：`S <x_mm> <y_mm> <z_mm> <底座> <肩> <肘> <腕> <夹爪> <旋转> <busy>`
——坐标是**整数毫米**（`%f` 在 newlib-nano 上要多占 2~3 KB Flash），角度是目标值，
`busy=1` 表示仍在运动，应先等 `DONE` 再发下一条 `M`。

**上电回执** `READY 3.0`：串口没反应时先按复位——看得到它说明固件和 TX 通路正常，
问题只在 RX 方向；看不到就是烧错了固件或接线/驱动有问题。

**错误码**：`ERR:CMD` 命令字错 / `ERR:ARG` 参数错 / `ERR:RANGE` 超范围（多半是单位笔误）/
`ERR:OUT` 超出工作空间 / `ERR:PATH` 路径中途出界 / `ERR:LONG` 单行超 64 字节 /
`ERR:BUSY` 回放中或运动中 / `ERR:FULL` 点表满 / `ERR:EMPTY` 点表空 /
`ERR:INDEX` 序号越界 / `ERR:FLASH` 擦写失败或代码已占到最后页。

## 6. 运动控制参数

| 宏 | 值 | 含义 |
|---|---|---|
| `MOTION_SPEED_DEFAULT` | 0.05 | 默认末端 50 mm/s（可用 `V` 在线改） |
| `MOTION_SPEED_MM_MIN/MAX` | 20 / 150 | 可调区间 |
| `MOTION_ACCEL` | 0.5 | 末端加速度 m/s² |
| `MOTION_STEP_MIN` | 0.0005 | 单次推进最小 0.5 mm |
| `MOTION_DT_MAX_MS` | 50 | 单次 Tick 最多补 50 ms |
| `MOTION_ARRIVE_EPS` | 0.0005 | 到位容差 0.5 mm |
| `MOTION_PATH_STEP` / `MAX_SAMPLES` | 0.005 m / 128 | 路径采样 5 mm、上限 128 点 |

梯形剖面实测（a=0.5, v=50mm/s）：300 mm 用 6.07 s（纯匀速 6.00 s），5 mm 单步 0.17 s，
中途改近目标、按键连发、反向回原点三种场景**全部零超调**。

**PWM**：TIM2/TIM3 完全一致，`PSC=71, ARR=19999` → 50 Hz，脉宽 500~2500 µs 对应 0~180°，
`CCR = 2000 × angle / 180 + 500`。

**机械参数**（`Servo_motor.c` 的 `mech_length`）：l0=0.08、l1=0.10、l2=0.09、l3=0.17，
总伸展 0.36 m（实测连杆约 35 cm）。行程限制仅**肘下限 45°**，其余 0~180°。

## 7. 示教与回放

```c
typedef struct { uint16_t a[6]; uint16_t dwell; } Play_Point;  /* 14 字节，无填充 */
```

| 项 | 值 |
|---|---|
| `PLAY_MAX_POINTS` | 64（RAM 896 B） |
| `PLAY_DEFAULT_DWELL_MS` | 500 |
| `PLAY_MS_PER_DEG` | 8（≈125°/s，段时长按**最大关节位移**算） |
| `PLAY_MIN_SEG_MS / MAX` | 150 / 2000 |

**Flash 布局**：最后一页 `0x0800FC00`，`Play_Header(12B) + 点表` 共 908 B，一页放得下。
头带 `magic "PLY3"`、`version`、`count`、点表 **CRC16-CCITT**；校验不过就当没存过，
退回空表——**宁可空也不能放出一串错角度**。`Play_Save()` 先比对链接脚本的 `_etext`，
代码区已吃到这页就直接失败、不擦。

**为什么自己插值**：`Servo_Motor_Updata()` 的节奏是 1°/50ms（转 90° 要 4.5 s），做回放太慢。
`Play_Tick()` 在主循环里按 `from + (to−from)×s(t)` 直接 `SetAngleNow()` 下发，
顺便对齐 `OldAngle`/`NewAngle`，两套插值不打架。时间用**绝对时刻差**而非累加器，
主循环偶尔被 OLED 拖慢 10 ms 只是少走一小步，误差不累积。

**`s(t)` 是梯形剖面**（而非线性）：线性插值每段开头瞬间到速、结尾瞬间停住，
连着几十个点跑会像抽搐，冲击还会叠加到结构。梯形后 `s'(0)=s'(1)=0`。
> 实现坑：匀速段常数项是 `r²/d` 不是 `r/d`，写成后者接缝处位置会跳一下。
> 代价：峰值速度是均值的 `1/(1−r)` 倍（r=0.25 时 1.33 倍），所以别再为了"看起来更快"
> 调小 `PLAY_MS_PER_DEG`。

**与 Motion 的三个冲突**：
① 回放绕过 `model_now()`，结束后必须用 `Motion_SyncFromCurrent()` 重新同步坐标
（读 `OldAngle` 实际位置，不是目标值），否则下一条 `M` 会从过期起点猛拽一下；
② 回放期间 `M` 回 `ERR:BUSY`（两个模块抢同一批 PWM，同时生效不可复现）；
③ 回放期间**按键照读不照做**——`Key_Check` 仍逐轮调用，否则 `Key_Flag` 锁存，
回放一结束四个键一次性全触发。

**事件回执**用独立事件而非塞进 `S` 行：`PLAY 3/8`、`PLAY END`。
`S` 的 11 字段是给所有上位机的契约，为新功能改公共格式不划算。

**按键启停**：`KEY_3 + KEY_4` 组合按住触发（四个键已占给 x/y 微调，长按又与连发同事件）。
用 `KEY_HOLD`（电平量、读不清除）拼组合并自己做 `combo_prev` 边沿检测，
否则按住不放会每 20 ms 翻转一次启停。已知副作用：先按的键会先走一次 5 mm 微调——
无害，回放下行的是绝对角度，第一个点立即纠正。

## 8. 上位机

单文件 `tools/serial_console.html`，零依赖、离线可用，**必须 Chrome/Edge**（Web Serial）。

**演示模式**（不接硬件）：点右上角「演示模式」或地址加 `?demo=1`。实现上只把 `writer`
换成一个假对象，上行数据仍走真实的 `onBytes`/`onLine`，因此渲染、日志、状态灯、示教面板
全部跑在真实代码路径上——不存在"演示一套、实机另一套"的漂移。模拟设备按 `protocol.c`
的语义回应 `M/G/R/Y/V/T/A/L/P/X/D/C/W/?`，`M` 走真实三连杆逆解，背后方向回 `ERR:OUT`，
`X` 停在当前姿态。自查脚本 `tools/_cdp_demo_test.py`（11 组用例，真实点击 + 读 DOM）。

| 区域 | 内容 |
|---|---|
| 左栏 | 坐标输入/单位切换、转向偏航（`Y`）、夹爪旋转、实时状态、示教点面板 |
| 中栏 | 姿态视图：2D 侧视剖面 + 工作空间底图 ↔ 3D 立体视图 + 平面点选 |
| 右栏 | 串口日志（RX/TX 分色、毫秒时间戳、HEX） |

**姿态视图把固件运动学在浏览器里复现了一遍**，且由 `?` 回报的**实际安装角**驱动，
不是用目标坐标反算——所以图上与目标十字的距离就是真实的 IK 误差。
常数 `CAL` 必须与 `model.c` 的 `SERVO_ZERO_A1/A2/A3` 一致（肘是 **178** 不是 180），
重新标定时两边一起改。

**3D 是手写投影，没引入 three.js**——整页要保持"双击即用"，为示意图拖进几百 KB 不划算。
只需要绕 Y 偏航、抬高俯仰、透视除法三件事。平面点选是投影的逆运算（屏幕坐标反求视线与
`y = planeY` 求交），自检办法是 `project → pickOnPlane` 走一圈回到原值。
三个取舍：取点用"当前目标高度"那层而非地面；拖拽与单击用 3 px 位移阈值区分；
工作空间底图在 3D 下置灰（那张图是 `(r,h)` 剖面，硬投影会糊成一团）。

**点表三层存储**（3.1）：

| 层 | 位置 | 生命周期 |
|---|---|---|
| RAM | 单片机 `s_pt[64]` | 掉电即失，供回放与脱机按键使用 |
| Flash | `0x0800FC00` | 掉电不丢，上电 `Play_Init` 载回 RAM |
| 网页缓存 | `localStorage` | 跟浏览器走，断联后的副本，可导出 JSON |

网页缓存**不能替代 Flash**：脱机回放读的是 RAM，RAM 来自 Flash；只存网页的话每次上电
都得连电脑推一遍，正好废掉 Flash 存储的唯一价值。`A` 命令的存在意义就是让"推回"成为可能
（`C` 清空 + 逐条 `A`，64 点约 0.3 s）。**必须一条一条等 `OK`**：RX 环形缓冲仅 1024 B，
64 条 `A` 约 1.6 KB，一口气倒进去必然溢出且**不会报错**——拿应答当节流阀最省事。

| # | 现象 | 根因 |
|---|---|---|
| 1 | `z≠0` 时末端最多偏 92.5 mm | 半径写成 `r = x`，漏了 z 分量（主循环里 z 恒为 0，从没暴露） |
| 2 | 大量可达点被判 `ERR:OUT` | 只试肘上解，实物是肘下工作 |
| 3 | 末端 2.2 mm 固定误差 | 行程检查容差 0.5° 太大，`180.49°` 判合格后被静默钳到 180 |
| 4 | 连发两条命令只执行第一条 | 按"总线静默"切帧而非按 `\n` 切行，两条命令挤进同一帧 |
| 5 | 链接失败 / Flash 紧张 | `strtof`、`%f` 在 newlib-nano 上多占 2~3 KB；改为手写解析 + 整数毫米 |
| 6 | 按一次键偶尔多走一步 | `if (Check(DOWN) \|\| Check(REPEAT))` 短路，REPEAT 标志滞留 |
| 7 | 断开后端口仍被锁 | `close()` 前读循环没退干净，需 cancel → 等 promise → releaseLock → close |
| 8 | 报错后 500 ms 被刷成"已到位" | 轮询覆盖了错误提示，加 `errLock` 锁状态灯 |
| 9 | 目标在背后时甩到正侧面还回 `OK` | `waist` 只钳位不检查，`x<0` 时静默压到 0/180 |
| 10 | 肘恒高约 2° | ZERO_A2 补偿方向搞反（加了 182，实际应减到 178） |
| 11 | `G 1` 夹爪动作不对 | PA6 是旋转、PA7 是开合，曾把两者设成同一角度 |
| 12 | 改上电初始姿态后夹爪歪 | 0° 是实测"平行地面"基准，不是随便一个位置 |
| 13 | 按 1366×768 截图"够用"，实际要滚动 | 无头视口=768，真实浏览器 UI 吃掉约 100 px，只剩 ~660 px |
| 14 | `-Wdiscarded-qualifiers` 警告 | 江科大 OLED 库字符串参数缺 `const`；重新拷贝会丢，需重打 |

> 教训中最贵的一条：中文"往下偏"有歧义——是"实际偏低"还是"需要往下调"？
> 必须追问，否则会把补偿方向改反。

## 10. 已知限制与待办

| 限制 | 说明 |
|---|---|
| 工作空间 66.3% 且非凸 | 远距离直线移动容易被 `ERR:PATH` 拒 |
| 单点精度 1~3 cm | 标定步长 5° + 舵机自身精度 |
| `x ≥ 0` | 底座舵机只覆盖正前方半平面 |
| 末端姿态不可控 | 腕角由冗余自由度自动选取，不能指定 |
| 夹爪/旋转无反馈 | `G`、`R` 只回"已下发"，是否夹住/到位靠外部确认 |
| 夹持时大角度旋转 | `SetAngleNow` 立即到位，惯性大，可能甩出工件 |
| 回放速度不跟 `V` | 由 `PLAY_MS_PER_DEG` 定死，改它要重编译 |
| 无硬件急停 | `X` 只能从串口发，最终手段仍是断电 |
| Flash 只有一页 | 存新的覆盖旧的，没有多套程序概念 |

**待办（按优先级）**：① 预设点位按钮（原位/取料/放置一键发送）；
② 路径校验放宽策略（先试直线，不行再分段）；③ 实测回填 `MOTION_SPEED_DEFAULT` 与
`MOTION_ACCEL`；④ 确认 `R` 的线性度与机械死点；⑤ 按实际工件调 `GRIP_ANGLE_CLOSE`。

## 11. 快速验证

```
?                 → S 280 100 0 90 120 69 42 0 0 0
M 0.36 0.08 0     → OK → DONE      全伸直，检查是否笔直
M 0.28 0.10 0     → OK → DONE      回初始位
G 1               → OK             夹爪收紧
R 60              → OK             转垂直（实测 60，不是 90）
M -0.28 0.10 0    → ERR:OUT        背后方向，应被拒
```

**示教三步**：摆姿态（`M`/按键）→ 记点（`T`）→ 试放（`P 1`）→ 满意后 `W` 存 Flash。
**脱机跑**：按住 `KEY_3 + KEY_4` 开始循环，再按一次停（不需要连串口）。
**断联找回点表**：网页「推回单片机」（`C` + 逐条 `A`）→ 再「存 Flash」才掉电不丢。
