# STM32 四轴机械臂

> STM32F103C8T6 + 6 路舵机的桌面级机械臂。三连杆逆运动学、笛卡尔直线插补、串口指令协议、
> 单文件网页上位机（含姿态可视化与工作空间底图）、关节空间示教 / 回放。

一个从零手写的嵌入式控制工程：不依赖任何中间件，从 PWM 脉宽到逆解到协议解析全部自己实现，
分层清晰，每一层都不知道上下层的内部细节。

**在线演示**：<https://chenguangzhai.github.io/robotic-arm/> — 网页上位机可直接打开看界面、
拖拽 3D 姿态视图；连硬件需 Chrome / Edge（Web Serial）。

---

## 特性

- **4 轴 + 夹爪**：底座偏航 / 肩 / 肘 / 腕 + 夹爪旋转 + 夹爪开合，共 6 路 50 Hz PWM
- **笛卡尔末端控制**：给定 `(x, y, z)` 坐标（米），内部完成三连杆逆解与舵机标定补偿
- **两种运动模式**
  - 笛卡尔直线插补：按**时间**推进（不是按主循环圈数），带梯形加减速
  - 关节空间示教回放：录点 → 插值回放，全程不做逆解
- **示教点掉电保存**：点表写入 Flash（上限 64 点），上电自动载入
- **串口文本协议**：单行指令、空格分隔、完整错误码，人可直接手打
- **网页上位机**：Chrome / Edge 的 Web Serial，单 HTML 文件、零依赖、离线可用，
  实时 2D 侧视剖面 / 3D 立体视图 + 工作空间可达域渲染

## 硬件配置

| 项 | 内容 |
|---|---|
| 主控 | STM32F103C8T6（72 MHz，64 KB Flash，20 KB RAM） |
| 框架 | STM32 HAL，CubeMX 生成（`Robotic_arm.ioc`） |
| 自由度 | 底座偏航 + 肩 + 肘 + 腕 + 夹爪旋转 + 夹爪开合 |

**舵机引脚**（TIM2 / TIM3，`PSC=71, ARR=19999` → 50 Hz，脉宽 500~2500 µs 对应 0~180°）

| 舵机 | 功能 | 通道 | 引脚 |
|---|---|---|---|
| 1 | 底座偏航 | TIM2_CH1 | PA0 |
| 2 | 肩（大臂） | TIM2_CH2 | PA1 |
| 3 | 肘（小臂） | TIM2_CH3 | PA2 |
| 4 | 腕 | TIM2_CH4 | PA3 |
| 5 | 夹爪旋转 | TIM3_CH1 | PA6 |
| 6 | 夹爪开合 | TIM3_CH2 | PA7 |

**其他占用**

| 功能 | 引脚 | 说明 |
|---|---|---|
| USART1 | PA9 / PA10 | 115200 8N1，接 USB-TTL（TX/RX 需交叉，必须共地） |
| OLED | PB8 / PB9 | 软件 I2C |
| 按键 Key1~4 | PA11 / PA12 / PA15 / PB3 | 低电平有效（PA15/PB3 需 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 释放） |
| LED | PC13 | |

> ⚠️ **舵机不要从板子 5V 取电**。6 路同时动作时堵转电流可达数安培，会拉垮板子电压，
> 表现为复位、OLED 花屏、舵机抖动。请用独立 5V/≥2A 电源，且 GND 必须与板子共地。

**机械参数**（`Hardware/Servo_motor/Servo_motor.c` 中的 `mech_length`，单位米）

| `l0` 立柱 | `l1` 肩→肘 | `l2` 肘→腕 | `l3` 腕→末端 | 总伸展 |
|---|---|---|---|---|
| 0.08 | 0.10 | 0.09 | 0.17 | 0.36 |

## 目录结构

```
.
├── Core/               CubeMX 生成：时钟、GPIO、TIM、USART、DMA、中断
├── Hardware/           手写业务代码，按职责分层
│   ├── Servo_motor/    舵机角度 → PWM 脉宽；model.c 逆运动学 + 正解
│   ├── Motion/         笛卡尔直线插补、梯形加减速、三重校验
│   ├── Play/           示教点管理、关节空间回放
│   ├── UART/           环形缓冲 + DMA（uart_app）；协议解析分发（Protocol）
│   ├── OLED/  Key/  LED/
├── Drivers/            STM32F1xx HAL + CMSIS
├── cmake/              gcc-arm-none-eabi 工具链文件
├── tools/              网页上位机 serial_console.html
├── docs/               工程开发总结.md ← 原理、参数来源、踩坑记录
└── archive/            1.0 / 2.0 历史版本（仅作演进记录，不再维护）
```

**分层约定**：`uart_app` 只搬字节，不懂什么是"命令"；`protocol` 只解析分发，不驱动舵机；
`motion` / `play` 不关心指令从哪来，两者互斥（回放期间运动指令回 `ERR:BUSY`）；
`model` 只管算角度，不知道舵机怎么接线。所以新增一条输入通道时，执行层零改动。

## 构建

前置工具：`arm-none-eabi-gcc`（需在 `PATH` 中）、CMake ≥ 3.22、Ninja。

```bash
cmake --preset Debug      # 或 Release
cmake --build --preset Debug
```

产物在 `build/Debug/`，可执行目标名为 `OLED`（CubeMX 沿用的历史名字）：

```bash
# 烧录示例（二选一）
STM32_Programmer_CLI -c port=SWD -w build/Debug/OLED.hex -rst
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "program build/Debug/OLED.elf verify reset exit"
```

> ⚠️ `CMakeLists.txt` 是**显式列源文件**，不是 glob。新增 `.c` 必须同时加进
> `target_sources` 和 `target_include_directories`，否则报 `undefined reference`。

## 串口协议

115200 8N1。单行文本，参数间空格 / Tab / 逗号均可，大小写不敏感，结尾 `\n` 或 `\r\n`。

| 指令 | 说明 |
|---|---|
| `M x y z` | 移动到 `(x,y,z)`，单位**米**。回 `OK` 表示已受理，到位推 `DONE` |
| `Y <度>` | 纯偏航：锁定当前半径与高度只转底座，±88° |
| `G 0\|1` | 夹爪：`0` 张开（0°），`1` 收紧（60°） |
| `R <角度>` | 夹爪旋转 0~180°（`0` 平行地面，`60` 垂直地面） |
| `V <mm/s>` | 末端巡航速度，20~150 mm/s |
| `T [ms]` | 把当前 6 个关节角记成一个示教点，停留时间默认 500 ms |
| `A a1..a6 [ms]` | 追加指定角度的点（不读当前姿态） |
| `L` | 列出点表 |
| `P [遍数]` | 回放，无参数 = 无限循环 |
| `X` | 停止回放 |
| `D <序号>` / `C` | 删单点 / 清空点表 |
| `W` | 点表写入 Flash |
| `?` | 查询状态 |

**状态应答**：`S <x_mm> <y_mm> <z_mm> <底座> <肩> <肘> <腕> <夹爪> <旋转> <busy>`，
固定 11 字段；坐标为整数毫米，`busy=1` 表示仍在运动。

**上电回执**：`READY 3.0` — 串口没反应时先按复位，看到它说明固件与 TX 通路正常，
问题只在 RX 方向。

错误码：`ERR:CMD` / `ERR:ARG` / `ERR:RANGE` / `ERR:OUT`（超出工作空间）/
`ERR:PATH`（直线路径中途出界）/ `ERR:LONG` / `ERR:BUSY` / `ERR:FULL` / `ERR:EMPTY` /
`ERR:INDEX` / `ERR:FLASH`。

## 网页上位机

直接用 **Chrome / Edge** 打开 `tools/serial_console.html`（需 `https` 或 `localhost`
环境才有 Web Serial 权限），点连接选择串口即可。

- 左栏：坐标输入 / 单位切换、偏航、夹爪、实时状态、示教点面板
- 中栏：姿态视图，2D 侧视剖面 + 工作空间底图，或 3D 立体视图（可切换）
- 右栏：串口日志，RX/TX 分色、毫秒时间戳、HEX 模式

姿态视图由 `?` 回报的**实际安装角**驱动，而不是用目标坐标反算——所以图上画的是
解算真正落到哪儿，与目标十字的距离就是逆解误差。视图常数 `CAL` 必须与固件
`model.c` 的 `SERVO_ZERO_A1/A2/A3` 一致（肘是 **178**，不是 180），重新标定时两边一起改。

结论版里的五个关键决策值得先看：为什么示教记**关节角**而不是坐标、为什么按**时间**
而不是按主循环圈数推进、为什么三重校验的顺序不能换、为什么减速上限用 `sqrt(2ad)`
而不是按比例分配时间、为什么纯偏航要独立成 `Y` 命令而不是改 `M` 的 z 语义。

## 已知限制

- 无 RTOS，单主循环轮询；OLED 区间扫描在运动/回放期间被跳过，否则会拖慢插值
- 逆解基于刚性 3R 平面模型 + 底座偏航，未建模关节柔性、舵机死区与负载下垂
- 示教点上限 64 个，受 Flash 页与 RAM 折中约束
- 上位机依赖浏览器 Web Serial，Firefox / Safari 不可用
